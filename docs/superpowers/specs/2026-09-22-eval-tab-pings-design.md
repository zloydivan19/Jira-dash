# Пинги во вкладке «Контроль оценки» — дизайн (этап 1: ручная отправка)

## Контекст и мотивация

«Контроль оценки» (`EvaluationTab.jsx` + `useEvaluation.js`) уже показывает
задачи в оценке с рассчитанным на клиенте SLA-статусом (зелёный/жёлтый/
красный/пауза/оценена). Сейчас единственное действие с этими данными —
просмотр и экспорт нарушений в Excel. Нужен способ прямо из интерфейса
напомнить (запинговать) человеку по конкретным задачам, не переключаясь в Jira.

Долгосрочная цель — автопинг, который сам шлёт напоминание, когда задача
подходит к границе SLA, независимо от того, открыт ли у кого-то браузер.
Эта версия сознательно ограничена **ручной отправкой** — автопинг требует
хранения Jira-токена на сервере и планировщика, это отдельный виток
архитектуры, который будет спроектирован отдельно после того, как ручная
отправка обкатается.

## Архитектура

### Канал доставки

Комментарий в саму задачу Jira, с упоминанием (`@mention`) исполнителя
(assignee) — человек получает штатное уведомление от Jira (email/значок),
без всякой новой внешней интеграции (Slack/Teams/email не нужны).

### Новый серверный роут

`server.js`: `POST /api/jira/comment`

- Вход: `{ issueKey: string, body: string, mentionAccountId?: string }`.
- Credentials — из тех же заголовков `x-jira-url`/`x-jira-email`/`x-jira-token`,
  что и во всех остальных роутах (`getCredentials(req)`), никакого нового
  способа авторизации не вводится.
- Форвардит в Jira: `POST {url}/rest/api/3/issue/{issueKey}/comment`.
- Тело запроса к Jira — ADF-документ (Jira Cloud API v3 comments API не
  принимает голый текст):
  ```json
  {
    "body": {
      "type": "doc", "version": 1,
      "content": [{
        "type": "paragraph",
        "content": [
          { "type": "mention", "attrs": { "id": "<mentionAccountId>" } },
          { "type": "text", "text": " <body текст с новой строки>" }
        ]
      }]
    }
  }
  ```
  Если `mentionAccountId` не передан (нет assignee) — content состоит только
  из текстовой ноды, без mention-ноды.
- Обработка ошибок — тот же паттерн, что в существующих роутах: `401` →
  `{ error: 'Неверные credentials' }`, иначе пробрасываем `error.message`/
  текст ошибки Jira, `timeout: 15000`.

### Множественная отправка

Jira не поддерживает комментирование нескольких задач одним запросом.
Фронтенд отправляет по одному `POST /api/jira/comment` на задачу,
параллельными пачками по 5 штук (тот же паттерн, что уже используется в
`useBugControl.js` для загрузки changelog батчами), собирая результат
`{ issueKey, ok: boolean, error?: string }` по каждой пачке перед переходом
к следующей.

## UI и выбор задач

### Выбор строк

В `GroupSection` (внутри `EvaluationTab.jsx`) добавляется столбец с
чекбоксом первым в каждой строке таблицы + чекбокс «выбрать все» в шапке
каждой из трёх групп (В процессе / На паузе / Оценены). Состояние выбора —
`selectedKeys: Set<string>` на уровне `EvaluationTab`, общее для всех групп
одновременно (можно выбрать задачи из разных групп сразу).

### Кнопка в тулбаре

Рядом с существующей «Экспорт SLA нарушений» — новая кнопка
«✉ Отправить пинг (N)», где N — размер `selectedKeys`. Задизейблена при
`N === 0`. Клик открывает панель композиции сообщения.

### Панель композиции

Модалка (аналогичная по паттерну существующим порталам фильтров в файле):

- Список выбранных задач: ключ + название; у каждой — крестик, чтобы убрать
  конкретную задачу из отправки прямо тут (без возврата в таблицу).
- Задачи без assignee помечены иконкой ⚠ с подсказкой «без исполнителя,
  уйдёт без упоминания» — не блокируют отправку.
- `<textarea>` для текста сообщения — один и тот же текст уйдёт во все
  выбранные задачи как есть (без подстановок/шаблонов — см. «Не в этой
  версии»).
- Кнопка «Отправить» — задизейблена, пока textarea пустая.

### Результат отправки

После клика «Отправить» панель не закрывается, а показывает построчный
результат под каждой задачей: ✓ отправлено / ✗ ошибка (текст ошибки Jira).
`selectedKeys` очищается только для строк с `ok: true` — проваленные
остаются выбранными, чтобы можно было поправить и повторить.

## Обработка ошибок и краевые случаи

| Ситуация | Поведение |
|---|---|
| Jira вернула 403/404/иную ошибку по одной задаче | Показываем её в строке результата, остальные задачи из batch продолжают отправляться независимо |
| Пустой текст сообщения | Кнопка «Отправить» неактивна |
| 401 (неверные credentials) | Стандартное сообщение `Неверные credentials`, как в остальных роутах |
| Задача без assignee | Отправляется без mention, обычным текстом, без ошибки |
| Повторная отправка той же задачи | Не блокируется — дедупликации/истории пингов в этой версии нет (понадобится для будущего автопинга) |

## Не в этой версии (сознательно исключено)

- Автопинг (fire-and-forget по расписанию, без открытого браузера) —
  отдельная задача, требует хранения токена на сервере + планировщика.
- Подстановки/шаблоны текста (`{key}`, `{дни в статусе}` и т.п.) —
  один и тот же текст на все выбранные задачи достаточно для первой версии.
- История отправленных пингов / дедупликация повторной отправки.
- Каналы, кроме комментария в Jira (Slack, Teams, email).

## Тестирование

Ручная проверка в браузере (в проекте нет автотестов, весь QA идёт через
`npm run build` + проверку в реальном Jira-инстансе):

1. Выбрать 2–3 задачи из разных групп (В процессе / На паузе / Оценены) →
   отправить → проверить в самой Jira, что комментарии появились с
   упоминанием исполнителя и получено уведомление.
2. Задача без assignee → комментарий ушёл без mention, без ошибки в панели.
3. Среди выбранных — задача с ошибкой (например, недостаточно прав) →
   остальные всё равно отправляются, ошибка показана только по ней,
   успешные снимаются из выбора, ошибочная остаётся.
4. Пустой текст → кнопка «Отправить» неактивна.
